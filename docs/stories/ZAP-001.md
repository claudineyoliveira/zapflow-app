# User Story: Estabilização do Core e Interface do ZapFlow

## 📖 Visão do Produto
O CEO solicitou que "essa parada do ZapFlow funcione". Isso significa que precisamos garantir que a espinha dorsal do sistema (Frontend ↔ Backend ↔ WhatsApp Web) esteja perfeitamente sincronizada, responsiva e pronta para uso em produção. 

## 🎯 Objetivo
Transformar o ZapFlow em uma **Máquina de Alta Conversão**, garantindo que a tela principal (Dashboard) se conecte de primeira com o QR Code do WhatsApp e que o usuário consiga subir números e fazer rodízio de mensagens sem telas travadas ou falhas de websocket.

## ✅ Critérios de Aceitação (DoD - Definition of Done)

### 1. Conexão Anti-Bloqueio (Websocket + Meta API)
- [ ] O Backend (Socket.io) deve notificar instantaneamente o Frontend quando o QR Code mudar.
- [ ] Se a Sessão do WhatsApp expirar ou cair, a interface do "Módulo de Disparo" deve mudar automaticamente para vermelho (Desconectado) e exibir o botão de reconectar na hora.

### 2. Painel de Controle UI/UX
- [ ] A tela de "Inteligência Anti-Bloqueio" não pode amassar em telas menores.
- [ ] O rodízio dinâmico de tempo (mínimo e máximo) não pode aceitar números negativos.

### 3. Autenticação (Clerk)
- [ ] As páginas de Sign-in e Sign-up já estão premium (com visual Glassmorphism), mas o botão de Logout deve realmente derrubar o token e desconectar o backend ativo deste usuário para evitar vazamento de memória.

## 🛠️ Instruções para o @dev
A partir deste documento, analise o arquivo `frontend/src/app/page.tsx` e o `backend/index.js` para conferir se todos os critérios acima são verdadeiros no código atual. Caso contrário, adicione as travas de segurança necessárias e comite as alterações.
